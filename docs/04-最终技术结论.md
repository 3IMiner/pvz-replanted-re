# 最终技术结论：为什么"100%原版 + 安卓原生 + 无模拟器"不存在

## 一句话结论

你要的三个条件两两组合都有解，但**三个同时满足，无解**：

| 条件组合 | 结果 | 状态 |
|---|---|---|
| 100%原版 + 无模拟器 | Windows/x86 原生运行（PC、主机） | ✅ 存在，但不是安卓 |
| 100%原版 + 安卓 | Winlator/Box64 翻译执行 | ✅ 存在，你已拒绝 |
| 安卓原生 + 无模拟器 | 重写编译（Unity/Android SDK） | ✅ 存在，但代码是重写的，你已拒绝 |
| **100%原版 + 安卓原生 + 无模拟器** | **不存在** | ❌ 无解 |

---

## 三层硬约束（每一层单独就足以否决）

### 1. 原生代码不能跨架构"转换"

游戏的核心逻辑在 `GameAssembly.dll` —— **87 MB 的 x86-64 机器码**（IL2CPP 把 C# 编译成机器码后的产物）。

- 安卓要的是 arm64 的 `.so`
- 机器码不能"翻译"成另一个架构的机器码后继续叫"原版代码"
- 不存在把 x64 DLL 转成 arm64 SO 并保持 100% 一致的工具

同理 `UnityPlayer.dll` 是 Windows 原生库，调用 `user32` / `d3d11` / `dxgi` / `xinput`。就算指令转了，这些 Windows API 在安卓上不存在——要有人实现它们，那**就是 Wine**，你已拒绝。

### 2. 没有可编译的源码工程

100%一致的前提是拿原工程切 Build Target 重新出包。但包里没有：

- `.cs` 源码（IL2CPP 编译后 IL 消失，逆向只能拿结构 + 汇编，不是可编译源码）
- `.unity` 场景工程（只有序列化数据）
- prefab 的脚本绑定（GUID 指向已编译脚本，重编后全断链）
- Addressables group 配置
- D3D11 shader 源码（需要 GLES/Vulkan 重编）

AssetRipper 能重建工程骨架，但导出的 812 个脚本方法体是空的（`return null`），不能编译出原版行为。

### 3. 官方没有安卓版

EA 明确表示 Android 无计划，手机端只有 iPhone（Apple Arcade）。没有官方 APK 可以拿来分解或对照。

---

## 为什么"动画"这个要求尤其致命

你特别强调动画也要完全一致。原版动画是 **Spine 骨骼动画**：

- 骨骼数据：`.skel` 二进制（在 `spineassets` 里）
- 图集：`.atlas` + 贴图
- 状态机：`AnimatorController` + 运行时代码控制切换

即使我把 Spine 数据和贴图全部导出来，让角色动起来，**驱动动画状态机的代码仍然是我写的**。原版什么时候播放哪个动画、混合时间、事件帧，全在那 145,833 个方法的机器码里。没有源码就没有 100% 一致的状态机。

---

## 所有可能路径的完整清单

| # | 路径 | 原版程度 | 模拟器 | 可行性 |
|---|---|---|---|---|
| 1 | Winlator 跑原版 exe | 100% | 有（Box64+Wine） | 已实现，你拒绝 |
| 2 | 拿 EA 内部工程重编 Android | 100% | 无 | 工程拿不到 |
| 3 | 静态机器码重编译 x86→arm64 | 理论100% | 无 | 研究级项目，SEH/COM/D3D 全要重写，且 UnityPlayer 是 Windows 库；实际不可行 |
| 4 | 重写（Unity/Android SDK） | 不是原版 | 无 | 已实现（33–51 MB 包），你拒绝 |
| 5 | 重写 + 原版素材 + Spine 动画 | 视觉接近，逻辑不同 | 无 | 可做，但不是100% |
| 6 | 网上找现成安卓版 | — | — | 不存在；搜到的全是 Winlator 套壳或假包 |

---

## 已经验证过的证据（不是猜测）

| 实验 | 结果 |
|---|---|
| 搜全网"PvZ Replanted 安卓 APK" | 只有 Winlator 套壳页面和 2.9 MB 假包；EA 官方明确无 Android 版 |
| Cpp2IL 三种输出模式 | 结构源码 12,578 个 .cs；方法体是 `return null` / `ldnull; ret` 桩 |
| AssetRipper 重建工程 | 2.6 GB、6 场景、812 脚本，但方法体为空 |
| IL2CPP 反编译尝试 | 只有类/偏移 dump（Zdex：49,743 类 / 565,304 函数），无方法体 |
| 安卓原生构建 | ✅ 成功（证明重写路线可行，但产物不是原版） |
| 模拟器实跑 | ✅ Winlator 包能玩到100%原版；✅ 原生重写包能跑但不是原版 |

---

## 结论

- 要 **100%原版内容**：只有 Winlator 路线（你已拒绝）
- 要 **无模拟器原生运行**：只有重写路线（你已拒绝）
- 要 **两者都要且动画完全一致**：不存在

这不是"再找找工具"能解决的问题。包里的东西物理上不够，而且缺的是最关键的那一块——可编译的原版代码和动画状态机。

---

## 如果你愿意退一步

最接近 100% 观感的现实方案是路径 5：**在现有原生包上接入原版 Spine 动画 + 原版 UI 图集 + 逐波脚本**，让植物僵尸真的按原版动作动起来、关卡按原版节奏出怪。

但即使做到最好，它仍然是"用原版素材重建的游戏"，不是原版代码本身。这一点我必须说清，不能骗你。

# 补充：动画素材的实际情况（已实测）

## 好消息：动画数据可以 100% 原版

原版角色动画是 **Spine 4.2.38** 骨骼动画，属于**资源数据**，不是编译代码。我已完整提取：

| 项目 | 数量 |
|---|---|
| 完整角色（.skel + .atlas + 贴图） | **117 个** |
| 其中植物 | 75 个（PeaShooter、SunFlower、Wallnut、CherryBomb、Chomper、Cactus、CobCannon…） |
| 其中僵尸 | 42 个（Zombie、Cone、Pail、Football、Gargantuar、Balloon、Bungee…） |
| 骨架文件 | 122 个 .skel（Spine 版本 4.2.38） |
| 图集描述 | 124 个 .atlas |
| 图集贴图 | 129 张 Texture2D |

样例已导出到 `spine_out\`：`PeaShooter.skel`(31 KB)、`Wallnut.skel`、`SunFlower.skel`、`Zombie_football.skel` 及对应 .atlas。

**结论：如果接入 spine-unity 4.2 运行时，植物和僵尸的动作可以做到与原版完全一致**——因为播放的就是原版骨骼数据。

## 坏消息：动画"什么时候播"仍然不是原版

骨骼动画本身是原版，但决定以下行为的代码在原版 `GameAssembly.dll` 里：

- 哪个状态触发哪个动画（种植、受到攻击、啃食、死亡）
- 动画之间的混合时间、事件帧、音效同步
- 随机待机、朝向翻转、啃食节拍

这些全部是编译后的机器码，没有源码无法 100% 复刻。

## 所以最终结论不变

| 你要求的部分 | 能否 100% 原版 |
|---|---|
| 草坪、区域背景、UI 图集 | ✅ 能（资源） |
| 植物/僵尸外观贴图 | ✅ 能（资源） |
| **骨骼动画本身** | ✅ 能（Spine 数据，117 个角色已提取） |
| 关卡号/波数/阳光/僵尸池 | ✅ 能（leveldata） |
| 植物/僵尸数值 | ✅ 能（PlantDefinition / ZombieDefinition） |
| **动画播放逻辑、战斗判定、AI、UI 流程** | ❌ 不能（编译机器码，无源码） |

**"整个游戏 100% 一致"依然不存在**，但差距已经从"动画都没有"缩小到"动画是原版的，只是触发逻辑是重写的"。

## 要接到这一步，需要做的

1. 把 spine-unity 4.2 运行时装进工程（GitHub 包或 .unitypackage）
2. 运行时加载 `.skel` + `.atlas` + 贴图，构造 SkeletonDataAsset
3. 植物/僵尸改用 SkeletonAnimation 渲染，播放 idle/eat/die
4. 保留现有逻辑驱动状态切换

这是"最接近原版"的现实终点。
