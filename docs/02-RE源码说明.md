# 逆向源码结果说明

> 目标：`PVZ Replanted`（Unity 6000.0.52f1 / IL2CPP Metadata 31.1 / 145,833 个方法）
> 工具：Cpp2IL 2022.1.0-pre.21（MelonLoader 自带）+ UnityPy

---

## 0. 一句话

**结构级源码：100% 拿到；方法体：只到汇编级。**

- ✅ 12,578 个 `.cs` 文件，含全部命名空间、类、嵌套类、字段（连字段偏移）、方法签名、特性、编译器生成的闭包 `< >c`、lambda
- ✅ 每个方法的 **x86-64 反汇编**（14,554 个文件，371.8 MB）
- ❌ 原始 C# 方法体（`{ }` 是空的）——IL2CPP 在打包时把 IL 编译成了原生代码，IL 本身不在包里

---

## 1. 为什么方法体是空的

我试了 Cpp2IL 的三种输出，结论很明确：

| 尝试 | 命令 | 结果 |
|---|---|---|
| Diffable C# | `--output-as diffable-cs` | 12,578 个 .cs，方法体 `{ }` |
| IL 恢复 | `--output-as dll_il_recovery` | DLL 里方法体是 `ldnull; ret`（2 条指令） |
| IL 恢复 + 调用分析 | `--use-processor callanalyzer` + `dll_il_recovery` | 同上，仍是桩 |

原因：Unity 的 IL2CPP 是 **AOT 编译**——C# → IL → C++ → 机器码，发布包里只剩机器码和元数据。要还原方法体，必须靠"从机器码反推 IL"（Cpp2IL 的 IL recovery），而这条链路在这版 Unity 6 构建上只产出了桩（这个 pre-release 对 6000.0 的恢复支持不完整）。

**但方法逻辑并没有丢**：它变成汇编躺在 `re\isil` 里。

## 5. 为什么"有源码"也编不出安卓版

即使忽略方法体缺失，重编还需要：

| 缺什么 | 说明 |
|---|---|
| Unity 工程 | `.unity` 场景、prefab、ScriptableObject 资产引用**全都不存在**，只有序列化数据 |
| 脚本绑定 | prefab 上的 `m_Script` 指向编译后的 type token，重编后 GUID 全部对不上，需要逐个重新挂 |
| Addressables 配置 | 分组、标签、catalog 生成规则不在包里 |
| Shader | 是 D3D11 编译产物，Android 需要重编 GLES/Vulkan |
| IL2CPP 运行时 | `GameAssembly.dll` 是平台原生库，arm64 版本需要原 C++ 中间代码 |
| 第三方 SDK | Steamworks / Sentry / Tekly / Reloaded.Input 都是二进制依赖，需替换 |

社区里所有 Replanted 改版（包括我做的那个）都走 **Harmony 运行时补丁**，不是重编——原因就在这。

## 6. 复现命令

```powershell
$cpp = 'modded/MelonLoader\Dependencies\Il2CppAssemblyGenerator\Cpp2IL\Cpp2IL.exe'

# 结构源码（12,578 个 .cs）
& $cpp --game-path './PVZ Replanted' --output-as diffable-cs --output-to 're/source'

# 逐方法汇编（371 MB）
& $cpp --game-path './PVZ Replanted' --output-as isil --output-to 're/isil'

# 数值表
python re\dump_defs.py
```

> Cpp2IL 会自动识别 Unity 版本（6000.0.52f1）和元数据版本（31.1），两个命令各跑 10–40 秒。
